## 2. 目标链路

```
digit-hub (psy 库存 / 测题)
        │
        ├─► 发货助手(XHS)  product_bindings + card_pool  → 小红书 IM 发卡
        │
        └─► 桥接同步 ──► 闲鱼 xy_cards(data) + xy_card_item_relations
                              → 闲鱼 IM / 定时补发
```

两种虚拟品：

| 类型 | 推荐库存 SSOT | 同步方式 |
|------|---------------|----------|
| **心象测链接** `link_card` | 云端 faka | 为闲鱼**单独 claim** 一批链入 `data` 卡；或订单级 allocate（进阶） |
| **普通卡密** `card` | 渠道分池或导出发标记 | 映射表 + 导卡；**禁止** XHS/闲鱼双端同时消耗同一条 unused |

## 3. 已有能力对照

### 发货助手

- 绑货：`product_bindings`（`product_id` 唯一）
- 卡池：`card_pool`（`unused|locked|used`）
- IPC 导卡：`product:add-cards`
- HTTP：**可读** `GET /api/products/bindings/:shopId`、`GET /api/products/cards/:bindingId?status=unused`  
  **无** `POST` 导卡（缺口，可后补）

### 云端 digit-hub

- `/api/faka/claim-links`、`/api/ship/allocate`、`/api/ship/bindings/sync`
- 账号快照**不同步**本地卡密库存

### 闲鱼

- `POST /api/v1/cards/batch-save`：创建 `data` 卡 + `item_ids` 绑定（**一键推荐**）
- `PUT /api/v1/cards/{id}`：整表替换 `data_content`
- `PUT /api/v1/cards/{id}/items`：改绑商品
- 匹配靠 `xy_card_item_relations`（勿只写遗留 `item_id` 字段）

## 5. 同步策略（写死）

**最高原则：按平台各自生成、各自发卡，库存互相隔离。**  
小红书只消耗 XHS/发货助手池；闲鱼只消耗闲鱼卡券池；**禁止**把同一批 unused 卡密拷到双端各发一次。

1. **幂等**：同一 `xy_item_id` 优先复用已有同名 `data` 卡，合并 `data_content`（去重换行）——仅针对**闲鱼自有库存**的追加导入。  
2. **防双花（强制）**：  
   - **禁止**默认 `pull_unused_cards` 作为长期方案（仅联调可临时用，且 `mark_exported_on_xhs` 必须理解风险）。  
   - **推荐** `claim_from_cloud` / 云端为闲鱼单独 claim、或闲鱼侧独立导入卡密；XHS 侧继续用自己的补货/claim。  
   - 链接类：订单级各自 `allocate`（进阶）最优。  
3. **绑定**：始终写 `xy_card_item_relations`；并建议打标 `fulfillment_type=virtual`。  
4. **触发**：手动脚本 / 定时任务 / 发货助手绑货成功后 webhook（P1）。

## 6. 实施里程碑

| Phase | 内容 | 验收 |
|-------|------|------|
| **P0** | 映射表 + 桥接脚本：从 `:19527` 拉 unused → 闲鱼 `batch-save`/`PUT` | 闲鱼商品付款自动发出导入的卡 |
| **P0b** | 云端 `claim-links` → 闲鱼导卡（心象测） | 链接卡可发 |
| **P1** | 发货助手增加 `POST /api/products/cards/:bindingId`；导后可选标记 exported | 可推式补货 |
| **P2** | 云端 `ship/bindings` 增加 `xy_item_id`；一键双端绑货 | 运营只绑一次 |
| **P3** | 订单级：闲鱼出单 → 云端 allocate → 发卡（零预存） | 库存占用最优 |
