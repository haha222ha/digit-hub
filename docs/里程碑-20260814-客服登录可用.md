## 二、根因备忘（为何会「登录认证已过期」）

文案来自 **walle-eva SPA**，不是本助手自绘：

1. 非 `Login` 路由下，任意已签名 API 返回 **HTTP 401**
2. 拦截器打点 `scene: "auth_expired"` → 弹窗「登录认证已过期，请重新登录！」
3. 同时清 Cookie

本阶段踩过的坑：

| 错误做法 | 后果 |
|---|---|
| 写出 `walle-eva-auth=undefined!!…` | SPA 全站 401 → 弹窗 → 清 Cookie |
| 仅凭 `a1`/`webId` 或脏 `walle-eva-auth` soft-ok | 假登录，随后必过期 |
| `get_csa_info` 业务失败就强制重登录 / 刷 URL | 冲掉已渲染会话列表 |
| 对通知/FAQ 等次要接口 401 全局踢登录 | 同上 |
| 强制 `loadURL(/cstools/chat)` 打断 dashboard | `ERR_ABORTED`、状态错乱 |

**合法会话标志**：

- 优先：`web_session` 或 `customer-shop-sid`（SSO）
- 或：合法 `walle-eva-auth` = `authToken!!accessToken`（两段均 ≥16 且非 `undefined`/`null`）

官方千帆：`setAutoLoginCookies(account)` 用真实 account 写 Cookie，再 `loadURL`。

## 四、硬约束（改坏则否决）

1. **禁止**写入 `walle-eva-auth`，除非 auth、access **两段**都通过 `isUsableAuthToken`
2. **禁止**用 `a1`/`webId` 判定已登录
3. **禁止**对 `get_csa_info` / 通知 / FAQ 等 401 触发强制重登录
4. **禁止** `get_csa` 失败时无 SSO 仍 soft-ok
5. **禁止**默认嵌套/依赖阿奇云账号与 Agiso WS
6. 登录入口必须是 **`cstools/login` + 客服邮箱**，不是 ark 上架扫码
7. `webSecurity: false`（客服列表依赖跨子域）勿随便改回 true
8. 版本号保持 ≥ `1.1.35`（当前对齐官方 `1.2.6`）
