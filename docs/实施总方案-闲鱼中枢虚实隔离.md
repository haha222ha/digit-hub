# 实施总方案：闲鱼中枢 × 虚实隔离 × 三系统对接

> 版本：v1.0 · 2026-08-17  
> 原则：**平台各自生成、各自发卡（库存隔离）**；闲鱼做销售前台；出单后再采实体；不改坏现网虚拟发货。

---

## 1. 目标态（一张图）

```
选品/采集 ──► 侵权过滤 ──► 闲鱼上架(虚/实打标, 多店差异化)
                              │
                     买家付款 pending_ship
                    ┌─────────┴─────────┐
                    ▼                   ▼
            virtual 履约            physical 代发
                    │                   │
     ┌──────────────┼──────────┐        ▼
     ▼              ▼          │   DropshipOrchestrator
 闲鱼卡池        XHS卡池      │        │
 (自有claim)   (发货助手)     │        ├─ PDD /order (已有)
     │              │          │        └─ XHS采购(后置)
     ▼              ▼          │
 闲鱼IM发卡    小红书IM发卡     │
                               └─ 禁止共用同一批卡密
```

**库存隔离铁律：**  
- 小红书只消耗发货助手 / 云端给 XHS 的 claim  
- 闲鱼只消耗闲鱼 `xy_cards` / 云端给闲鱼的 **独立 claim**  
- 不允许「从 XHS unused 拷到闲鱼再各发一次」作为正式流程

## 3. 四条工作流（按业务拆）

### 流 A｜虚拟：闲鱼卖评测/资料（主力，优先）

1. 云端为闲鱼 **单独 claim** N 条链接/卡密 → 写入闲鱼 `data` 卡券 + 绑 `item_id`  
2. 发货助手侧继续自己的补货/claim（另一池）  
3. 闲鱼付款 → 现有 AutoDeliveryHandler 发卡  

**验收：** 闲鱼拍一单发出链接；XHS 再拍一单发出**另一条**链接；两边库存互不影响。

### 流 B｜虚拟：小红书继续卖（维持现状）

不改主路径；只要求运营绑货时不要和闲鱼共用卡池。

### 流 C｜实体：闲鱼卖 → PDD 采购（第二优先）

1. 上架时打标 `physical` + `upstream_sku`（PDD goods/sku）  
2. 付款 → **跳过卡券** → dropship job  
3. 调 PDD `/order`（地址从闲鱼收件人标准化）  
4. 运单回填闲鱼（先 stub，后真实 consign）  

**验收：** 一笔实体测试单：闲鱼 pending → PDD 出现待付/已下单 → job 推进到 tracking/done。

### 流 D｜上架供给：采集 → 过滤 → 闲鱼多店

侵权过滤 + 主图/标题差异化后再发 10 店；与发卡并行，可稍后。

## 4. 实施阶段（建议排期）

### 第 0 周｜冻结与基线（0.5 天）

- [ ] 确认现网闲鱼账号 connected、虚拟测品仍能自动发  
- [ ] 文档对齐：隔离规则已写死（本文 + `评测发卡-闲鱼导卡绑货对接.md`）  
- [ ] 明确：正式环境禁用「拷 XHS unused → 闲鱼」  

### 第 1 周｜流 A 打通（虚拟隔离导卡）**【先做】**

| 步骤 | 做什么 | 谁/哪里 | 验收 |
|------|--------|---------|------|
| A1 | 实现 `claim_from_cloud`：云端 claim → 闲鱼 `batch-save` | `ops/xy_card_bridge.py` + digit-hub token | 脚本跑通 |
| A2 | 映射表：`psy_test_code` ↔ `xy_item_id`（一测题一闲鱼品） | `xy_card_bridge_map.json` | 配置清晰 |
| A3 | 闲鱼商品绑卡 + 实拍一单 | 运营 + 挂机 | 自动发出**闲鱼池**链接 |
| A4 | XHS 同测题再拍一单 | 发货助手 | 发出**另一条**，证明隔离 |
| A5 | （可选）低水位：闲鱼池 < N 自动再 claim | scheduler 或手动 | 不断货 |

**本周不做：** 实体代发、10 店矩阵铺货、XHS App 逆向。

### 第 2 周｜流 C 打通（实体 PDD）

| 步骤 | 做什么 | 验收 |
|------|--------|------|
| C1 | `pending_ship` 虚实分流（physical 不进卡券） | 虚拟回归仍过 |
| C2 | `PddUpstreamAdapter` 调现有 `:8000/order` | Mock 换成真下单 |
| C3 | 地址 normalize 接通 | PDD 收件人正确 |
| C4 | 1 单联调（`auto_pay=false` 先人工付） | job 有上游单号 |
| C5 | 运单回填：先 stub，再真实 mtop | 状态 done |

### 第 3 周｜流 D 半自动上架 + 多店纪律

| 步骤 | 做什么 |
|------|--------|
| D1 | 侵权/品牌词过滤 MVP（拦截后再上架） |
| D2 | 闲鱼上架包：标题改写 + 主图二创（沿用现有豆包规则若适用） |
| D3 | 10 店：一机一号一代理；禁止同图同步擦亮；错峰发布 |

### 第 4 周+｜增强（按需）

- 订单级 allocate（闲鱼出单再向云端要链接，零预存）  
- 云端 bindings 带 `xy_item_id` 一键双端绑货（仍是**两池库存**）  
- XHS 人工采购工单 → 后期 App 自动采  
- 真实运单 consign、毛利看板、经营性阈值预警

## 7. 风险与节奏控制

| 风险 | 应对 |
|------|------|
| 卡密双花 | 隔离生成；监控两池库存 ID 不交叉 |

| 10 店矩阵 | 先 1 店跑通再扩；差异化+隔离设备 |
| PDD 质量/仅退款 | 先少品类；人工付；抽样 |
| 改坏虚拟发货 | 每 Sprint 虚拟回归清单 |
